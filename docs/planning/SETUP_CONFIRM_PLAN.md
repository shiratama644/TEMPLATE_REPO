# SETUPCONF-1: 計画提示後に対話式承認を受ける

> 対応 task-list ID: `SETUPCONF-1` (`docs/task-list.md`)
> 計画書テンプレート: `docs/planning/_TEMPLATE.md` 準拠

## 1. 開始前確認

- 固定ブランチの HEAD・作業ツリーを確認する。サンドボックス再構築時は作業ツリーを退避・照合してから復旧する。
- BUNSETUP-3 と BUNAUDIT-1 の完了、および BUNSETUP-4 の実機検証待ちを確認する。
- `AGENTS.md §6.1`、`scripts/setup.ts`、`tests/setup.test.ts` を読み、§5・§7 の境界を確認する。

## 2. 目的 (Why)

`bun run setup` を対話式で起動した利用者が、`--apply` の指定を知らなくても計画を読んでから `y/N` で適用を承認または拒否できるようにする。

## 3. 変更範囲 (Scope)

変更対象: `scripts/setup.ts`、`tests/setup.test.ts`、README と `AGENTS.md §6.1`、計画・索引・進捗・活動ログ。

変更しない: 非対話式の `--yes --apply` による適用条件、OS パッケージごとの別承認、生成物の内容、過去の監査ログ。

## 4. 禁止事項

- 承認前にファイル作成・バックアップ作成・依存導入を始めない。
- `--yes` 単独でファイル変更または OS パッケージ導入を許可しない。
- 計画拒否・空入力・`--dry-run` で変更しない。テストを弱めて通さない。
- 不明点は推測で埋めず、§7 の停止条件に従って質問する。

## 5. 完了条件 (DoD)

- [x] 対話式は計画表示後に `[y/N]` を尋ね、`y` のみ（互換入力 `yes` も可）で適用し、`N` と空入力では不変更。
- [x] 対話式の `--apply` は質問を省略しない。`--dry-run` は常に不変更。
- [x] 非対話式は従来どおり `--yes --apply` のときだけ適用し、OS 導入の別承認を維持。
- [x] CLI ヘルプ・README・規約を実態と同期し、疑似端末を使った回帰テストと `bun run check` が通る。
- [x] `docs/task-list.md` の状態・進捗・証拠を更新し、リポジトリ固有の不変パスを変えない。

## 6. テスト方法

| 層 | 実施 | 確認内容 |
|---|---|---|
| Unit | `bun test` | 既存の非対話・dry-run の安全境界 |
| Component | 疑似端末で `bun run setup` | `y` 適用、`N` / 空入力で不変更、`--apply` だけでは承認を省略しない |
| E2E | `bun run check` | 文書・型・Lint・テストを含む全ゲート |
| 実環境 | 未実施 | OS パッケージの実導入と他 OS 実機は BUNSETUP-4 |

## 7. 停止条件

次の場合は作業を停止し、変更せず報告する:
- 仕様書同士の矛盾や、対話承認の意味を変えるユーザー判断が必要な場合。
- タスクの変更範囲を超える破壊的変更が必要な場合。
- 開始時点の未確認変更を安全に退避・照合できない場合。

## 8. 完了時に行うこと

1. 差分自己レビューと `git diff --check` を行う。
2. `bun run check` を実行し、各ゲートとテスト件数を記録する。
3. `docs/task-list.md` の証拠を更新し、Conventional Commits で commit する。
4. 固定ブランチに push し、PR の CI と残余リスクを報告する。

## 10. 設計詳細・仕様

`--dry-run` なら計画だけ表示して終了。端末で `--yes` がなければ計画表示後に必ず `[y/N]` を尋ね、`y` / `yes`（大小文字を問わない）のみを承認する。その他は拒否し、不変更で終了する。端末なし、または `--yes` 指定時は従来の `--yes --apply` の安全境界を維持する。OS の各コマンドにはさらに独立した `yes` 入力を必要とする。

## 11. リスク・Gotchas

CLI に TTY を渡さない通常の `spawnSync` は対話経路を通らない。Linux の `script(1)` で疑似端末を作り、プロンプトの出現後に回答を書き込む。非 Linux 環境では疑似端末テストの実行可否を別途確認する。
