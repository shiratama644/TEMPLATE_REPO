# ADR-0003: 文書とコミットメッセージの言語を「日本語と英語のみ」に機械で制限する

**Date**: 2026-10-26
**Status**: accepted
**Deciders**: リポジトリ所有者（「コミットやファイルは日本語または英語のみを許可するのでそのチェックを追加してください」）、作業 Agent

## Context

本リポジトリの文書は日本語で書かれている（`.agent/rules/03_doc-style.md` §1「本文は**日本語**。コード識別子・技術固有名詞は英語のまま」）。ところが**他の言語が混入しても、日本語の漢字に見えるため読者が気づけない**。AGENTSYNC の作業中に 5 回発生した:

| 混入 | 正しい日本語 | 見つけた場所 |
|---|---|---|
| U+951A U+5B9A（「錨定」の簡体字形） | アンカリング | 計画書 |
| U+4F9D U+8D56（「依存」の簡体字形） | 依存 | ADR-0002 の草稿 |
| 中国語の疑問形 3 字（U+600E U+4E48 U+505A） | どうやるか | `.agent/skills/context-budget/SKILL.md` |
| U+53CD U+9988（簡体字） | フィードバック | ADR-0002 |
| U+624B U+52A8（「手動」の簡体字形） | 手動 | コミット `5a10b4d` のメッセージ |

5 件のうち 4 件は「書いた本人が後で読み直して」偶然発見したもので、**発見が運に依存していた**。5 件目のコミットメッセージは push 済みで、履歴の書き換えが禁止（`.agent/settings.json` の deny に `git commit --amend`・`git push --force*`）されているため未修正のまま残った。さらに言語ゲートの開発中に、shell フックのコメントへハングル 3 字が混入していた例も全体走査で発見した（`704c398` で修正）。

`AGENTS.md §3.1` の方針は「LLM に linter の仕事をさせない」だが、言語については linter が存在しなかった。

## Decision

**標準ライブラリ（`unicodedata` と Python の日本語 codec）だけで判定する `scripts/check_language.py` を作り、pre-commit の 2 フック（`language` = pre-commit stage / `commit-msg-language` = commit-msg stage）でゲート化する。** `make lang` と `make check`（CI と同じ入口）から実行する。

判定の中心は「**日本語で使う文字は EUC-JP / CP932（JIS X 0208 + NEC/IBM 拡張）で符号化できる**」という事実で、これに Unicode の一般カテゴリとスクリプト名を組み合わせる:

| 対象 | 判定 |
|---|---|
| ASCII・ラテン文字・ひらがな・カタカナ | 許可（英語と日本語） |
| 記号・句読点・数字・空白（カテゴリ `P*` `N*` `S*` `Z*` `C*`）、絵文字・矢印・罫線・CJK 約物・全角形 | 許可（言語は文字に宿るので記号は判定しない） |
| ハングル・キリル・ギリシャ・アラビア・ヘブライ・タイ・デーヴァナーガリー ほか（Unicode 名にスクリプト名を含む） | **error** |
| U+4E00–U+9FFF・U+F900–U+FAFF の漢字で CP932/EUC-JP に符号化できないもの | **error**（簡体字など） |
| U+3400–U+4DBF・U+20000 以降の漢字で符号化できないもの | **warn**（日本語の表外漢字の可能性があるため error にしない） |

失敗は **error のみ**（warn は報告するが exit 0）。スクリプトは既存の `check_doc_links.py`・`check_mermaid.py` と同じ流儀で、**内蔵 fixture 8 件による自己検査**を走査前に実行する（スクリプトを壊したときに「たまたま PASS」しないため）。

## Alternatives Considered

### Alternative 1: 「日本語コーデックで符号化できるか」だけで判定する

- **Pros**: 実装が 3 行で済む。追加の辞書も依存も要らない。
- **Cons**: 実測で **4 種類の誤判定**があった。① 絵文字（U+2705 など）が全て NG になる ② キリル・ギリシャは JIS X 0208 に**含まれる**ため検出できない ③ 繁体字の大半（U+6A23 U+5011 U+9019 U+88E1 U+4F86 U+500B U+6642 U+5BE6）は CP932 の NEC/IBM 拡張に含まれ検出できない ④ 日本語の表外漢字（U+20B9F U+29E3D）が NG になる。
- **Why not**: ①④ は正当な日本語を止める偽陽性で、ゲートが使われなくなる。② は検出漏れ。単純方式は**プロトタイプで実測して棄却した**（判定表は `docs/planning/LANGGATE_PLAN.md` §10.2）。

### Alternative 2: 語彙リスト（U+4F9D U+8D56 や U+8FD9 U+4E2A を含む語）で照合する

- **Pros**: 語として確実に止められる。共通漢字だけの中国語文も検出できる（文字単位方式の限界を補える）。
- **Cons**: **正当な日本語を大量に誤検出する**。実際に試したところ「起点・要点・時点」「反転・反映・反対」が引っかかった（「点」「反」を含む語をリストに入れると偽陽性になる）。リストの保守も必要で、網羅性は永久に保証できない。
- **Why not**: 誤検出はゲートの信頼を壊す。文字単位方式なら「動の簡体字形 U+52A8」のように**日本語に存在しない字形**だけを確実に止められる。語単位の検査は行わないことを計画書 §10.3 に明記した。

### Alternative 3: 言語判定ライブラリ（`langdetect`・`lingua`・`cld3` など）を使う

- **Pros**: 統計的に「何語か」を判定できる。混在文書にも強い。
- **Cons**: 実行時依存が増える（`scripts/` の他 2 本は標準ライブラリのみ）。短い文字列（コミットメッセージの 1 行、コードのコメント）では判定が不安定で、確率的なので**同じ入力で結果が変わりうる**。誤検出の原因を説明しにくい。
- **Why not**: ゲートは「なぜ止まったか」を利用者が理解でき、自分で外す判断（`IGNORE_PATHS` / `SKIP=language`）ができる必要がある。codec ベースの判定は理由をコードポイントで説明できる。

### Alternative 4: 検査を追加せず、規約（rules）に書くだけ

- **Pros**: 依存も設定も増えない。
- **Cons**: 既に `rules/03_doc-style.md` に「本文は日本語」と書いてあった上で 5 回混入した。**書かれた規約は破られる**（ADR-0002 と同じ結論）。
- **Why not**: 混入は目視で発見できないため、機械ゲート以外に再発防止策がない。

### Alternative 5: コミットメッセージは検査しない（ファイルのみ）

- **Pros**: フックが 1 つで済む。`commit-msg` stage の導入も不要になる。
- **Cons**: 実際の混入 5 件のうち 1 件は**コミットメッセージ**で起き、しかも履歴の書き換えが禁止されているため**永久に残る**（`5a10b4d`）。ファイルだけ守っても同じ事故が繰り返される。
- **Why not**: 修正不能な場所にこそゲートが要る。`default_install_hook_types` は既に `[pre-commit, commit-msg]` で、追加の導入手順も不要だった。

## Consequences

### Positive

- 簡体字・ハングル・キリルなどの混入が commit 前に止まる。**導入時に実バグを 1 件発見した**（フックのコメントのハングル 3 字 → `704c398`）。
- 標準ライブラリのみで、辞書データもネットワークも不要。既存 2 本のチェッカと同じ流儀（自己検査 fixture 内蔵）。
- 判定理由がコードポイントで出力されるので、利用者が自分で誤検出か判断できる。
- 手元（`make lang` / `make check`）と CI が同じ入口。

### Negative

- 日中共通の漢字だけで書かれた中国語文は**検出できない**（§10.3）。完全な言語検査ではない。
- 繁体字中国語の大半も CP932 の NEC/IBM 拡張に含まれるため検出できない。
- フックが 2 つ増え、`make check` は 11 フックになった。
- **違反例を文書に書くときはコードポイントで書く**必要がある（字面で書くとその文書自身がゲートに止まる）。スクリプトの fixture も `\uXXXX` エスケープで書いている。

### Risks

- **リスク**: 正当な日本語（表外漢字・異体字・新しい約物）を error として止め、ゲートが回避される。
  **緩和**: 拡張領域の漢字は warn に落とした。「髙」(U+9AD9)「﨑」(U+FA11)「德」「禮」が CP932 に含まれることを fixture で固定し、導入前にリポジトリ全体（162 ファイル）で error 0 件・warn 0 件を実測した。新しい誤検出が出たら `IGNORE_PATHS` か判定表を直す。
- **リスク**: 「ゲートが緑なのに何も守っていない」no-op 化（`agents-md-lint` で実際に起きた）。
  **緩和**: **負のテストを完了条件にした**（計画書 §5）。簡体字ファイル・ハングル・キリル・簡体字コミットメッセージで exit 1、正常系で exit 0 を実測し、自己検査の判定ロジックを壊すと自己検査が失敗することも確認した。
- **リスク**: 派生プロジェクトで他言語のファイル（翻訳・テストデータ）を正当に持てない。
  **緩和**: スクリプト冒頭の `IGNORE_PATHS`（正規表現）を編集する手段と、`SKIP=language git commit` / `SKIP=commit-msg-language git commit` を docstring と `.pre-commit-config.yaml` の注記に書いた。
- **リスク**: warn が増え、無視されるようになる。
  **緩和**: 失敗は error のみに限定。warn は「日本語の表外漢字の可能性」という狭い意味に絞り、導入時点で 0 件にした。
