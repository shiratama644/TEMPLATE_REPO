# 有界のバグ監査ループ

根拠: `tests/agents.test.ts`・`tests/git_report.test.ts`・`tests/plan-verify.test.ts` の再現可能な負例。

## 実行手順

1. **範囲と停止条件を記録**: 機能・信頼境界、対象 OS、反復上限・未検証を計画書と `docs/task-list.md` に記す。完全性を保証しない。
2. **基準値**: `bun install --frozen-lockfile` → `bun run check` → `bun run knip` と `git status --short` を記録。合計は出力から数える。PASS と skip/blocked/未実行を混ぜない。
3. **探索**: 既存テストと設計判断、実際の呼び出し経路、境界入力、複数失敗の優先順位を調べる。ゲートが exit 0 でも、no-op でないことを成功時の**有出力**と異常入力時の exit 非 0 で確認する。ラッパー・symlink・CI の実際の入口をテストする。
4. **再現と修正**: 一つの現象につき固定入力の負例を先に追加し、失敗を確認。原因を絞り、最小修正し、同じ負例が緑になることを確認する。プレビューと適用の間に安全性を再検証する。ツール不在のテストは純粋関数の検査と実機検証を分離し、後者を「PASS」としない。
5. **反復**: 修正した経路と隣接経路をもう一度異常入力で調べ、別の根本原因があれば 3→4 を繰り返す。上限に達した/2回続けて新しい現象が見つからない/安全境界を越える場合は停止して残りを明示。テスト件数やチェック数は実測し、暗算しない。
6. **全体検証**: `bun run check`・`bun run knip`・`git diff --check`、変更したゲートの負例、CI を確認。変更が PR 上で未確認なら完了扱いしない。`verification-before-completion` の手順を適用。

記録例: `反復 N: 探索対象 → RED の入力と出力 → 原因 → GREEN とゲート → 残り`。発見がなければ「発見なし・検査範囲」を明示し、全不具合不存在とは書かない。
