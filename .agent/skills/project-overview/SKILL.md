# Project Overview — 汎用エージェント作業テンプレート

> このリポジトリは、AI Agent に**ソフトウェア開発だけでなく、文書作成・調査・データ整理・設定作業などを規律立てて進めさせる**ためのテンプレートです。
> GitHub の「Use this template」から新しいリポジトリを作成し、プロジェクトごとに書き換えて使うことを想定しています。
>
> **実プロジェクトへ合わせるときは、本ファイルを読む前に [`project-init`](../project-init/SKILL.md) を使う。**
> 初期設定が終わると、本ファイル自体が「このプロジェクトの全体像」に書き換えられる。

## 目的

- **速く大量に作ることではなく、常に復旧可能で、壊れた状態を長時間維持しないこと**を最優先とする。
- 小さく実行 → 検証 → 修正 → 記録 → 次の作業、のサイクルを徹底する。
- タスク管理・ドキュメント・Agent 設定を統一し、どの分野のプロジェクトでも同じ運用を流用できる状態を保つ。

## このテンプレートに含まれるもの

| パス | 役割 |
|---|---|
| `AGENTS.md` | Agent が必ず守る作業規約。§1〜§5・§7・§8 は汎用、§6 はプロジェクトごとに記入 |
| `.agent/` | Agent 設定（rules / skills / hooks / agents など） |
| `docs/` | ドキュメント一式。`task-list.md`（進捗の正本）・`arch/`（仕様）・`planning/`（計画）・`research/`（調査）・`audit/`（監査）・`ops/`（運用） |
| `README.md` | プロジェクトの概要（テンプレート利用時に書き換える） |
| `LICENSE` | ライセンス |

ソフトウェアのソースコードや特定言語のツール設定は含まれない。必要になったら、プロジェクトごとに追加する（`tech-stack` スキル参照）。

## ドキュメント構成

```
docs/
├── README.md          # 全ドキュメントの目次
├── task-list.md       # タスク管理の唯一の正本（進捗・証拠）
├── arch/              # 仕様書（どう作るか / 何を作るか）
├── planning/          # 計画書（_TEMPLATE.md 形式）
├── research/          # 調査結果
├── audit/             # 差分・バグ・品質の監査
├── ops/               # 運用手順
```

## 進捗管理

- 正本は `docs/task-list.md`。チャット・Issue・AI の完了報告と矛盾する場合は本ファイルを正とする。
- 進行中タスクは原則 1 件。複数を同時に進めない。
- タスク ID は再利用しない。中止したタスクは行を消さず「対象外」にして理由を残す。
- 完了は AI の自己申告ではなく、証拠（検証結果 / コミット SHA / 成果物 / 実測値）で判定する。
