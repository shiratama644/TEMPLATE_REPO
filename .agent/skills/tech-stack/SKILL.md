# Tech Stack Skill — 技術選定と記録の指針

> このテンプレートは特定の言語やフレームワークを前提にしない。プロジェクトの目的に応じて技術を選び、
> 選んだ結果を **AGENTS.md §6.1（環境・ツールチェーン・検証コマンド）** に必ず記録する。

## 1. 基本原則

- **既存の流儀を優先**: 既にリポジトリにある言語・ツール・設定があれば、それに合わせる。新しいツールを足す前に既存で足りるかを確認する。
- **最小構成から始める**: 最初は「実行」「検証」の2つが回る最小構成にし、必要になった時に追加する。
- **再現性**: バージョンを固定する（ロックファイル・バージョン指定ファイル・依存のピン留め）。「自分の環境でだけ動く」状態を作らない。
- **検証手段を先に決める**: 何で正しさを確認するかを決めてから実装・作成に入る（§3.1 参照）。
- **記録する**: 採用した技術・バージョン・検証コマンドは `AGENTS.md §6.1` に書く。判断理由が重要なものは `docs/adr/` に残す。

## 2. 分野別の選び方（例）

| 分野 | 作るもの | 検証の考え方 | 選定時の確認事項 |
|---|---|---|---|
| ソフトウェア | アプリ・ライブラリ・CLI | 型・静的解析・単体テスト・ビルド | 言語のバージョン方針、依存の管理方法、CI の有無 |
| Web アプリ | Web サイト・SPA・SSR | 上記 + E2E テスト + 表示確認 | フレームワーク、ブラウザ対応範囲、デプロイ先 |
| ドキュメント | 仕様書・マニュアル・記事 | リンク切れ・表記ゆれ・目次整合性 | 出力形式（Markdown / PDF 等）、用語集の有無 |
| データ | 集計・分析・変換 | スキーマ検証・再実行の一致・集計値の突き合わせ | 入出力形式、データの置き場所（Git に入れない大容量データは外部保存） |
| 設定・運用 | 手順書・IaC・自動化 | 構文チェック・dry-run / plan | 対象環境、権限、ロールバック手順 |

## 3. 記録フォーマット（AGENTS.md §6.1 に書く内容）

```markdown
### 6.1 環境・ツールチェーン・検証コマンド
- 言語・ランタイム: （名称とバージョン）
- 依存管理: （ツール名と、ロックファイルの扱い）
- 検証コマンド:
  - 型・静的解析: `<コマンド>`
  - 単体テスト: `<コマンド>`（watch モードではない形）
  - ビルド: `<コマンド>`
- 初期セットアップ: `<手順>`
```

## 4. ハマりどころ（一般）

- **バージョン不一致**: 手元のバージョンと CI・他者の環境が違うと再現しない。バージョンは明示する。
- **生成物のコミット**: ビルド成果物・キャッシュ・依存ディレクトリは `.gitignore` に入れ、リポジトリに含めない。
- **大容量データ**: 数百 MB 級のデータ・バイナリは Git に入れず、外部ストレージや取得手順で扱う。
- **環境依存のエラー**: 外部接続・権限・OS 差異によるエラーは、コードの不具合と区別して記録する（`sandbox-constraints` 参照）。

## 5. 分野固有のスキル

ソフトウェア開発・Web 開発に特化したスキル（`testing` / `e2e` / `ci-quality-gates` / `determinism` / `import-boundaries` / `memory-leak` / `zero-alloc`）は、該当する分野のプロジェクトでのみ使う。詳細は `.agent/skills/index.md` を参照。
