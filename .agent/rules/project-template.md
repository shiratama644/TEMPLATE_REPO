# Rule 07: プロジェクト固有の遵守事項（テンプレート）

> 優先度: **HIGH** — このファイルはテンプレート利用時にプロジェクトごとに書き換える
>
> **手順の正本は [`project-init`](../skills/project-init/SKILL.md)。** 本ルールは埋める項目のチェックリスト。
> 承認前にファイルを書き換えない。質問と計画の承認を先に行う。

このファイルは `AGENTS.md §6` と対応する。新規プロジェクトを作成したら、`project-init` に従い以下を埋めること。

**現状（このリポジトリは空）**: アプリのコードもテストもサンプルも無い。`README.md` と `docs/arch/architecture.md` は最小限の stub。あるのは作業規約（`AGENTS.md`・`.agent/`）、検証ゲート（`bun run check` の 9 ゲート・`bun run knip`）、Git フック、CI と Dependabot、`docs/` の枠、運用 CLI（GitHub 設定・Git レポート）、OS 判定（`scripts/setup-env.ts`）。

## 1. 環境・ツールチェーン（§6.1相当）

- 使用言語・ランタイムとバージョン（このテンプレートの既定は Bun と TypeScript。変えるなら理由と検証方法を書く）
- 依存管理の方法と固定方針（ロックファイルの扱い）
- 検証コマンド一覧（現状は `bun run check` の 9 ゲートと `bun run knip`。テストは無い。追加したら `AGENTS.md §6.1` と一致させる）

## 2. サンドボックス制約（§6.2相当）

乗り越えず、迂回する。修正対象ではない恒常的制約とその対処を書く。

| 制約 | 対処 |
|---|---|
| 外部 API に到達不可 | モック・サンプルデータで代替。実 API の検証は人間に依頼 |
| GUI / ブラウザ / 特定ハードウェアが使えない | 実行できない検証は CI または人間側で行う |

## 3. リポジトリ固有の Git 制約（§6.3相当）

- 書き込みが許されないディレクトリ・ファイル（外部由来の不変データなど）
- 変更禁止の領域とその理由

## 4. 実装ルール（§6.4相当）

- 採用する設計方針・命名規則・依存の方向
- 過去に踏んだ地雷と回避策

## 5. Lint・フォーマット特有ルール（§6.5相当）

- 抑制コメントの置き場所・自動生成ファイルの除外設定

## 6. 成果物・表現ルール（§6.6相当）

- 出力フォーマット（例: 文書のスタイル、図の規格、データの単位）
- 用語集・表記ゆれの統一ルール

## 7. ドキュメント運用（§6.7相当）

- テンプレート同梱のドキュメント規約を既定とする
- 構成・命名規則・運用ルール: `docs/README.md`
- タスク進捗管理: `docs/task-list.md`（唯一の正本）
- 仕様書: `docs/arch/` / 計画書: `docs/planning/`（`_TEMPLATE.md` 形式）
