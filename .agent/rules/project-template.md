# Rule 05: プロジェクト固有の遵守事項（テンプレート）

> 優先度: **HIGH** — このファイルはテンプレート利用時にプロジェクトごとに書き換える

このファイルは `AGENTS.md §6` と対応する。新規プロジェクトを作成したら、以下を埋めること。

## 1. 環境・ツールチェーン（§6.1相当）

- 使用言語・ランタイムとバージョン（例: Python 3.13 / Node.js 24 / Rust stable / なし）
- 依存管理の方法と固定方針（ロックファイルの扱い）
- 検証コマンド一覧（型・Lint・テスト・ビルド等。`AGENTS.md §6.1` と一致させる）

## 2. サンドボックス制約（§6.2相当）

乗り越えず、迂回する。修正対象ではない恒常的制約とその対処を書く。

| 制約 | 対処 |
|---|---|
| 外部 API に到達不可（例: api.example.com） | モック・サンプルデータで代替。実 API の検証は人間に依頼 |
| GUI / ブラウザ / 特定ハードウェアが使えない | 実行できない検証は CI または人間側で行う |

## 3. リポジトリ固有の Git 制約（§6.3相当）

- 書き込みが許されないディレクトリ・ファイル（例: 外部由来の不変データ）
- 変更禁止の領域とその理由

## 4. 実装ルール（§6.4相当）

- 採用する設計方針・命名規則・依存の方向
- 過去に踏んだ地雷と回避策

## 5. Lint・フォーマット特有ルール（§6.5相当）

- 抑制コメントの置き場所・自動生成ファイルの除外設定

## 6. 成果物・表現ルール（§6.6相当）

- 出力フォーマット（例: 文書のスタイル、図の規格、データの単位）
- 用語集・表記ゆれの統一ルール

## 7. ドキュメント運用（§6.7相当）

- テンプレート同梱のドキュメント規約を既定とする
- 構成・命名規則・運用ルール: `docs/README.md`
- タスク進捗管理: `docs/task-list.md`（唯一の正本）
- 仕様書: `docs/arch/` / 計画書: `docs/planning/`（`_TEMPLATE.md` 形式）
