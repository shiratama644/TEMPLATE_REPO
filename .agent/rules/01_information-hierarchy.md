# Rule 01: 情報の正と編集ルール

> 優先度: **CRITICAL** — 他の全ルールに優先する

## 1. 「正」の対応表

| 用途 | 参照すべき情報源 | 編集可否 | 備考 |
|---|---|---|---|
| 作業規約・開発ワークフロー | `AGENTS.md` | ✅ 編集可（プロジェクト固有 §6 のみ） | 常に正。速さより復旧可能性を優先 |
| 進捗・タスク状態の正本 | `docs/task-list.md` | ✅ 編集可（状態・証拠の更新） | 矛盾時は本ファイルを正とする |
| 仕様・構成 | `docs/arch/*` | ✅ 編集可 | どう作るか・どういう構成か |
| 判断の記録 | `docs/adr/` | ✅ 新規ファイルを追加 | 過去の ADR は書き換えない |
| 個別タスクの計画 | `docs/planning/*` | ✅ 編集可（計画時） | `_TEMPLATE.md` 準拠 |
| 調査結果 | `docs/research/*` | ✅ 編集可 | 情報源と確認日を書く |
| 監査・差分・問題の記録 | `docs/audit/*` | ✅ 追記（`activity.md` は追加のみ） | 時点の記録。書き換えない |
| 運用手順 | `docs/ops/*` | ✅ 運用時に更新 | 秘密情報は書かない |
| ドキュメント目次 | `docs/README.md` | ✅ 追加・削除時に必須更新 | 全ドキュメントの入口 |
| 検証手段 | `AGENTS.md §6.1` | ✅ プロジェクトごとに記録 | Agent はここに無いものを実行しない |
| 分野別の知識・手順 | `.agent/skills/*/SKILL.md` | ✅ 知見が得られたら更新 | 再利用可能な事実・手順 |
| プロジェクト概要 | `README.md` | ✅ 編集可 | 目的・使い方 |
| Agent 設定 | `.agent/settings.json` | ✅ 編集可（チーム共有） | permissions, hooks, env |
| 個人オーバーライド | `.agent/settings.local.json` | ✅ 個人のみ（gitignore） | 個人の上書き |

## 2. 鉄則

1. **進捗は `docs/task-list.md` のみを正本とする**。チャット・ログ・他の文書と矛盾したら、task-list を正とする。
2. **仕様は `docs/arch/` が正本**。計画は `docs/planning/`、調査は `docs/research/`、監査は `docs/audit/`。
3. **スキルは事実・手順、AGENTS.md は規約**。重複させない。規約は AGENTS.md、事実・手順はスキルへ。
4. **ドキュメントの追加・削除・移動時は必ず `docs/README.md` の目次を更新する**。参照切れを残さない。
5. **プロジェクト固有の情報は `AGENTS.md §6` と `skills/project-overview` に集約する**。それ以外の部分はテンプレートとして流用できる形に保つ。

## 3. 禁止操作

- `docs/task-list.md` のタスク ID の再利用
- `AGENTS.md` の汎用節（§1〜§5）の勝手な削除・大幅な書き換え（プロジェクト固有は §6 へ）
- 完了したタスクの計画書・記録の削除（履歴として残す）
- 過去の ADR・`activity.md`・`.agent/logs/` の書き換え（追記のみ）
