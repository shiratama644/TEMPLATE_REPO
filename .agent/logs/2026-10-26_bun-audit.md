# Bun 版セットアップの不具合監査

> Date: 2026-10-26(JST) / Commit: 作業完了後に採番 / PR: 5

## 1. 指示内容

「バグを完全に全て見つけ出して修正する」という依頼に対し、無欠陥の数学的保証はできないことを前提に、Bun CLI・全テンプレート・17 機能・検査・Git フック・CI の再現できる不具合を監査して修正する。安全境界と残る実機未検証項目を偽らず記録する。

## 2. 実行内容

| 分野 | 見つけた原因と修正 |
| :--- | :--- |
| 入力・安全性 | 不正な preset / language・null / 型不正・誤字の config が適切なエラーにならない問題、末尾ハイフン等の不正名、`.git` 下へ設定を書ける問題、シンボリックリンク先へ既存 manifest のバックアップを書ける問題、dangling symlink の manifest を置換する問題を修正。ネストした `--save-config` を作成可能にし、バックアップは一意なディレクトリへ保存 |
| 機能互換 | Python 等の言語に使えない JS 専用機能を黙って選択済みと表示していた。明示指定はエラー、プリセット由来は除外内容を表示。単独 coverage に必要な Vitest を追加 |
| 生成物 | Docker の Bun 依存導入と `.dockerignore`、library の版・exports・型宣言・size-limit プリセット・Changesets changelog 依存を補完。Python FastAPI は専用 `.venv` と pip の editable install、Rust Axum は cargo fetch を行う。Python CLI / FastAPI の起動を OS 別にし、`.gitignore`・devcontainer の導入コマンドを追加 |
| ツール群 | Vitest の初期テスト、Playwright の CLI / HTTP スモークテスト、cspell / knip の生成物除外と必要な単語、既存 hook を保護する opt-in Husky インストーラーを追加。生成物のアプリ固有テストや実ブラウザ検査は利用者が追加する |
| 検査・フック | 文書リンクの URL エンコード・クエリ・ルート相対パスを扱い、閉じられていない Mermaid フェンスを検出。Git フックの所在を worktree 対応の `git rev-parse --git-path hooks` で調べ、既存 commit-msg を検出して導入を拒否。テンプレート由来テストとの衝突を避けるため、基盤の Bun テスト対象を `tests/setup.test.ts` に限定 |

## 3. 実測結果と注意点

- Bun テストは **30 件・220 assertions** PASS。異常系から先に書いて失敗を再現してから修正した。`bun install --frozen-lockfile` と `bun run check` の7ゲートは最終差分で PASS（リンク 144 ファイル、Mermaid 12 ブロック、言語 185 ファイル）。
- 一時ディレクトリで Vite / Next の TS・JS、Vite / Next monorepo の **6 通りのビルド**を再確認。library と full の `bun install` / `build` / `publint` / `size` は PASS。full の `test` / `coverage` / `e2e` / `knip` / `spell` も適切な初期フィクスチャと設定で実行確認。Vite / Next / 両 monorepo の Playwright HTTP スモークは PASS（ブラウザは使わない）。
- Python FastAPI は生成から `.venv` での pip install とモジュール import まで実測。Python CLI は `bun run start` で実行。検証用の Bun と Python venv はリポジトリ外に置き、**OS パッケージは導入していない**。
- 既存 `.git/hooks/commit-msg` を保護するため Git フックの登録は exit 1 で拒否。生成した Husky インストーラーも同じ hook を検出して拒否し、`core.hooksPath` は不変。
- macOS / Windows / Termux の実機、Go / Rust の実ビルド、Rust の外部 crate 導入、Docker エンジンでの build、apt / brew / winget / pkg の実インストール、Playwright の実ブラウザ操作は未検証。GitHub Actions の結果は push 後に確認する。有限のテストは未知の全バグの不存在を証明しない。
